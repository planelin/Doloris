# 决策实验站

一个纯静态的「决策实验站」网站，用一条清晰的四阶段路径展示自动决策链中的关键切面：先确认谁还在负责，再完成状态交接，随后做出可解释的选择，最后把结果沉淀为可复用的记录。

## 目录结构

```
decisionlab/
├── index.html              # 首页：实验站介绍、四阶段导航与设计原则
├── PROGRESS.md             # 六项完成清单
├── README.md               # 本说明文档
├── assets/
│   ├── style.css           # 全站样式（暗色赛博风：深色背景 + 霓虹蓝绿）
│   └── app.js              # 导航高亮与卡片入场等基础交互
├── pages/
│   ├── 01-heartbeat.html   # 阶段 01：心跳检测
│   ├── 02-takeover.html    # 阶段 02：会话接管
│   ├── 03-decision.html    # 阶段 03：决策代理
│   └── 04-report.html      # 阶段 04：终态报告
└── data/
    └── config.json         # 两次决策的实际结果（theme、lang）
```

## 本地打开方式

本站不依赖构建工具与后端服务，所有文件均为静态资源，直接打开即可浏览。

- 方式一：在文件管理器中进入 `decisionlab/`，双击 `index.html`，浏览器会直接渲染首页。
- 方式二：从首页顶部导航进入四个主题页，或直接打开 `pages/` 目录下的任意页面。

如果需要通过本地服务器访问，可以在 `decisionlab/` 目录中启动任意静态文件服务器，例如：

```bash
python -m http.server 8000
```

随后在浏览器打开 `http://localhost:8000/` 即可。

> 说明：页面通过相对路径引用 `assets/` 与 `pages/`，请保持目录结构完整，不要单独移动某个 HTML 文件。

## 页面内容

- **首页**：介绍实验站的定位，提供通往四个主题页的导航、路径概览与四条设计原则。
- **01 心跳检测**：解释为什么需要心跳、心跳应携带什么信息、超时阈值如何设定，以及心跳之后交接为何才开始。
- **02 会话接管**：说明接管的触发条件、交接包必须包含的上下文、权限与边界的重新声明，以及接管失败时的降级路径。
- **03 决策代理**：讨论目标与约束的分离、不确定性下的证据评估、选择的可追问性，以及执行与责任。
- **04 终态报告**：描述完整报告的结构、偏差分析的方法，以及记录如何转化为可复用的知识。

每个主题页均包含四个实质内容小节，至少三段论述，并提供「上一站 / 下一站」的阶段导航。

## 决策记录

本站在构建过程中经过两道决策门，实际结果如下（同时记录于 `data/config.json`）：

| 决策门 | 事项 | 选项 | 最终结果 |
| --- | --- | --- | --- |
| 决策门 A | 全站视觉主题 | 主题甲：暗色赛博风（深色背景 + 霓虹蓝绿）<br>主题乙：亮色极简风（白色背景 + 黑字橙色点缀） | 主题甲：暗色赛博风 |
| 决策门 B | 全站文案语言 | 选项甲：全部简体中文<br>选项乙：全部英文 | 选项甲：全部简体中文 |

### 决策门 A：视觉主题

选定的暗色赛博风以 `#050b10` 附近的深色为底，配合霓虹青绿（主色 `#2ef2d0`、辅助色 `#8dff5a`）作为强调色，并加入细网格背景、发光边框与状态高亮，用于承载心跳、接管、决策与报告这类偏技术控制台的阅读场景。

### 决策门 B：文案语言

全站页面文案统一为简体中文，包括首页、四个主题页、导航标签与阶段标识，确保概念表述与项目既有文档保持一致。

## 技术说明

- 纯静态实现，无框架、无构建步骤、无外部依赖。
- 使用语义化 HTML 与响应式 CSS，支持桌面与移动端布局。
- 样式集中在 `assets/style.css`，通过 CSS 自定义属性管理配色，便于后续整体换肤。
- 包含跳转到主要内容的无障碍链接，并通过 `prefers-reduced-motion` 适配减少动画的系统偏好。
