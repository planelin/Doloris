01 / HEARTBEAT MONITORING

心跳检测

用固定节奏的周期信号判断 Agent 是否仍在推进、停滞或已经离线，为任何后续接管提供第一手证据。

检测层周期：15 秒超时：3 个周期当前状态：正常

机制目标

心跳不是证明任务成功，而是证明执行进程仍在工作。每个 Agent 在长任务循环中上报递增序号、阶段说明和最近一次动作时间；监管端只比较时间与进度，不依赖模糊的“忙碌”描述。

判定规则

  • 在连续 3 个采样窗口中收到递增心跳，标记为“前向运行”。
  • 时间未超时但序号不变，标记为“停滞观察”，保留一个宽限窗口。
  • 超过 45 秒未收到心跳，立即升级为“疑似离线”，冻结新的高风险动作。
  • 迟到的旧心跳不会覆盖更新序号，避免乱序数据制造虚假恢复。

响应流程

发现停滞时，监管系统先保存最后进度与未完成动作，再尝试轻量唤醒；若第二个窗口仍无回应，就会话状态和授权凭证交给接管流程。整个过程保留时间线，不直接假定 Agent 已失败。

失效边界

心跳只能说明“进程活着”，不能说明“方向正确”。因此它必须与端点探针、验收清单和授权边界共同使用，不能单独作为任务成功或继续放权的依据。

实时信号

收到15s
延迟0.8s
连续128

核心原则

先区分停滞与失败，再决定是否介入；任何恢复动作都必须留下可追溯记录。
