会话接管

当原 Agent 无法继续推进时，由监管者安全夺取执行权，继承已验证上下文并从最近的检查点继续。

恢复层接管延迟：42 秒上下文：已保留当前状态：已介入

机制目标

接管的目标是恢复任务，不是制造第二个并行的“主 Agent”。新执行者必须获得唯一会话锁、最近检查点、未完成动作和当前授权范围，并在继续前确认没有副作用动作被重复提交。

接管步骤

  • 冻结原会话的新动作并标记接管原因与证据。
  • 写入会话清单：目标、阶段、检查点、外部资源和未完成调用。
  • 等待原执行者停止或到达强制隔离时限。
  • 由新执行者获取唯一锁，回放关键状态并核对幂等键。
  • 从检查点继续，首个高风险动作仍需遵守授权边界。

上下文一致性

不直接信任自由文本总结。接管前会同时检查工具调用记录、文件版本和结构化检查点，三者冲突时以可验证的外部证据为准，并降低新会话的自动决策权限。

防双写要求

文件、消息、订单和外部 API 调用都必须带幂等键。没有唯一锁或无法确认旧会话已停止时，只允许执行只读探测，不允许继续写入。

核心原则
