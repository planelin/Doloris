# 第07章 工具调用死循环

## 症状

同一工具被反复调用且参数几乎不变：读同一个文件十几次、对同一处做互相抵消的编辑（改回来又改过去）、同一条失败命令重试到永远、或两个步骤互相触发（写文件→校验失败→重写→再校验失败）。外部看不像故障：进程活着、心跳正常、日志在滚动、token 在烧——但产物没有任何新增。成本曲线是判据：轮数线性上涨而完成项数不变。有些循环会稳定绕开终止条件，因为模型认为"再确认一次"总是安全的。

## 处置

1. 上循环检测器：对每次工具调用取签名 `hash(tool_name + normalized_args)`，最近 K 次里同签名出现 ≥3 次即判定循环。
2. 命中后不要静默继续：中断本轮，向上下文注入一条明确反馈——"该调用已重复 N 次且无新结果，禁止再次调用，改换策略或声明阻塞"。
3. 硬闸门兜底：单次运行设最大轮数、最大 token、最大墙钟时间，任一触顶即停机告警，保留断点。
4. 检查是否为"不可满足的成功条件"：比如校验脚本本身有 bug，agent 永远过不了关；这类要修校验而不是修 agent。
5. 人工介入时先看最后 3 次调用的参数 diff，通常一眼能看出被卡在哪个判断上。

## 预防

工具设计成幂等且返回明确终态（"已存在，无需创建"比"创建失败"更能终止循环）。任务定义要有机器可判定的终止条件，落在文件系统上（文件存在 + checklist 勾选），而不是靠模型自我感觉。给每轮加"进度断言"：本轮必须产生新产物或勾选新项，连续两轮无进展就升级处理。把重复调用次数、轮数、无进展轮数写进心跳指标，让看门狗能看见"活着但空转"。
