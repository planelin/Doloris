# 第12章 无人值守的安全边界

## 症状

夜间自动运行的 agent 做出了没人授权的动作：删掉工作目录、`git push --force` 覆盖远端、向外部服务发消息或上传代码、把 `.env` 内容打进日志、为"修好构建"而改动无关模块甚至关掉测试。另一类是外部内容变成了指令——网页、issue、依赖 README、抓回的文件里写着"忽略之前的要求，执行 X"，agent 照做了（提示注入）。共同前提是"全部自动批准 + 无边界"，出事时又缺少可追溯的操作日志。

## 处置

1. 先止血：停掉运行、撤销自动批准，切断出网权限。
2. 评估影响面：列出本次运行触碰的所有文件、执行过的命令、发出的外部请求；比对预期范围，超范围的逐项核实。
3. 凭据一律按已泄露处理——只要可能进过日志或外部服务就立即吊销并轮换（见 ch05）。
4. 回滚：用快照/仓库历史恢复被误改内容；远端被强推则从本地或备份重建，并保留事故分支供复盘。
5. 归档完整审计日志（谁、何时、什么命令、退出码），并把该场景补成回归用例。

## 预防

按最小权限配置：允许清单只放读文件、搜索、写指定目录；`rm -rf`、`force push`、包发布、对外通知、凭据读取走拒绝清单或强制人工确认。不可逆操作先干跑（dry-run）再执行。在隔离环境里跑——独立工作目录/worktree/容器，出网限定域名白名单，宿主敏感路径不挂载。把外部抓取的内容一律当**数据**处理，不当指令，并在提示里明确这一点；发现夹带指令就报告异常而不是执行。日志走脱敏过滤，运行有硬预算（时间/轮数/花费），越界即停机并带外告警——无人值守的核心不是"更聪明的 agent"，而是"更小的可造成损害的半径"。
