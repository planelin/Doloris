# 第01章 心跳检测与卡死判别

## 要点

长任务“还在运行”不等于“还在进展”。监管器应区分进程存活、事件产出和业务进展三层信号：PID 只能证明进程未退出，心跳证明调度器仍有响应，只有里程碑计数、文件版本或步骤状态前进才证明任务有效推进。心跳超时必须结合最后有效活动时间、预期步骤耗时和当前阻塞点判断，不能用一个固定秒数覆盖下载、推理、编译等差异巨大的阶段。

## 做法

任务每完成一个可观测步骤就原子更新带序号、时间戳和阶段名的心跳文件；监管器采用软阈值告警、硬阈值回收两段策略。软超时先采集线程栈、子进程树和最近日志，硬超时再发送 TERM，宽限期后 KILL。若 agent 支持协作取消，应让它自行保存断点后退场；重建时从已完成步骤继续，并把卡死样本写入故障账本。

## 反例

只看“进程存在”便认为夜间任务健康，或让工作线程直接刷新心跳而主循环已经死锁，都是假存活。另一个极端是心跳迟到十秒就杀进程，会把正常的长编译反复打断，既丢失现场又永远无法完成大步骤。
