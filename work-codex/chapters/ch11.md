# 第11章 终态报告与现场保全

## 要点

任务无论成功、失败、超时还是人工终止，都必须进入唯一终态并生成同一结构的报告。报告应回答目标是什么、实际完成了什么、验收证据在哪里、产生了哪些外部副作用、消耗了多少资源、还剩什么风险以及可安全执行的下一条命令。终态一旦提交不得被后续日志悄悄改写；修正信息应追加为关联事件，保持审计链完整。

## 做法

在任务结束前冻结日志、配置版本、代码提交、产物清单、关键环境摘要和错误现场，按敏感级别打包并计算哈希。对失败保留容器或临时目录的只读快照、线程栈和最小复现；对成功则保留可重建证据和清理记录。报告生成器从结构化状态与验收器读取事实，不直接采用模型自述，并校验所有证据路径确实存在后原子发布。

## 反例

只留下一句“执行失败”，会迫使下一班人员重新探索甚至覆盖现场；清理脚本先删临时目录、后生成报告，会让最关键的错误证据永久消失；把 agent 的成功总结当终态报告，则未通过测试、未提交或已发生重复副作用都可能被掩盖。
