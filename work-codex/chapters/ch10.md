# 第10章 故障注入与混沌测试

## 要点

监管能力不能等真实事故时才验证。混沌测试要在隔离环境主动注入进程退出、网络延迟、DNS 失败、429/5xx、代理认证失败、磁盘写满、权限拒绝、时钟跳变和电源中断，并观测系统是否正确限流、保存断点、轮换端点、告警和停止执行不可逆动作。测试目标应包括恢复时间、数据完整性和成本上限，而非只证明“最终还能跑通”。

## 做法

从只读影子任务开始，按单故障、组合故障、持续故障逐级扩大爆炸半径；每次实验声明稳态指标、停止条件和回滚方案。使用确定性种子让案例可复现，校验恢复后没有重复副作用和文件损坏。将关键事故模式固化为常态回归，在发布前和生产小流量中运行；失败实验直接生成工单和缺失监控项，直到修复或明确接受风险。

## 反例

只在健康路径跑单元测试，第一次断网就会把任务永久卡住；在生产直接杀掉唯一 worker 来“验证恢复”，本身制造事故；只观察 agent 是否重启，却不核对进度文件、产物哈希和外部消息，会漏掉重放造成的重复副作用。
