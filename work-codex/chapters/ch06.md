# 第06章 出站代理与网络诊断

## 要点

无人值守任务常运行在受限网络，必须显式区分直连、系统代理、企业代理与隧道出口，并让监管器知道每一跳的预期行为。健康检查要沿真实出站路径执行，记录 DNS 结果、连接目标、代理状态码、TLS 协商和证书链；不要把“本机能打开网页”误当成“agent 进程继承到了正确代理变量和凭据”。

## 做法

以配置清单统一注入 HTTP_PROXY、HTTPS_PROXY、NO_PROXY 和证书信任，启动时生成不含密钥的有效配置摘要，并做一次目标端点端到端探测。失败后按层诊断：DNS、路由、代理认证、CONNECT、TLS、应用协议，保存可脱敏的命令结果与 trace ID。代理切换采用受控逃生通道，限制目标域名和时长，恢复后立即回切并记录偏差。

## 反例

节点不可达时直接关闭 TLS 校验或全局绕过代理，会把暂时性的连接问题升级为长期安全问题；多个组件各自读取不同环境变量，会导致探针成功而 worker 全部失败；日志只写 generic timeout，事后无法判断请求究竟卡在本地 DNS、代理还是远端服务。
