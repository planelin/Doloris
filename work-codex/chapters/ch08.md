# 第08章 干预存档与一键回档

## 要点

任何人工干预都应被视为正式事务，而不是直接改几行状态。介入前保存任务状态、进度版本、队列、配置、模型与提示词版本、产物清单和最近轨迹；明确操作者、原因、预期效果与到期时间。回档目标不是模糊的“撤销”，而是回到某个带哈希的可恢复快照，并知道回档后哪些外部副作用仍无法撤销。

## 做法

把任务目录、版本库提交或对象存储快照统一编号，回档前先做新备份，再停止新写入、排空或冻结 worker，原子恢复状态与文件，最后从目标断点重新调度。涉及数据库或外部 API 时使用补偿事务、撤销脚本或人工确认清单，并在轨迹中建立“干预前、回档后、重放后”三段关联记录。提供默认演练模式，先展示差异再执行。

## 反例

直接在运行中的目录删文件、改 JSON 后重启，会留下内存与磁盘状态不一致；只回滚本地文件却忘记撤回已发送消息，会形成双重通知；没有记录干预原因，数日后无人知道进度为何跳变，也无法判断是否应再次应用该修复。
