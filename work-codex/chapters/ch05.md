# 第05章 供应商探针与端点轮换

## 要点

多供应商架构要持续测量“当前从本机看哪条路径可用”，而不是依赖静态配置或全局健康页。探针应覆盖 DNS、TCP/TLS、认证、最小有效推理和流式首包，按供应商、区域、端点与凭据维度分别统计成功率、延迟和限流。健康是短时租约，不是永久标签；主端点恢复后也应经过观察期再逐步回切。

## 做法

把端点列表做成带权重和熔断状态的池，失败时先在同供应商内轮换，再跨供应商切换；每个请求记录实际端点与尝试链。切换必须满足能力兼容、数据驻留和成本策略，不能只看可用性。对 429、5xx、超时和鉴权失败使用不同冷却时间，并用低流量探测决定恢复；配置变更经版本化发布，使故障时能回退到已知良好集合。

## 反例

把探针只做成 HTTP 200 检查，会漏掉认证过期、配额耗尽或模型名失效；一次超时就永久摘除节点，会让瞬时抖动触发大规模漂移；把所有工具流量自动切到未授权地区，虽恢复了服务却违反合规与数据边界。
