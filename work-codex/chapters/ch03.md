# 第03章 会话预分配与轨迹日志

## 要点

长任务开始时就应预分配稳定会话标识、根任务 ID、子任务命名空间和产物目录，后续重启、换 worker 或切换模型都必须沿用同一逻辑身份。轨迹日志不是简单 console 文本，而是只追加的结构化事件：时间、序号、参与组件、动作、输入摘要、结果、错误指纹、费用和关联 ID。这样才能还原“谁在何时基于什么状态做出了哪一步”。

## 做法

日志采用 JSON Lines 或同等级格式，敏感值在入口脱敏，大对象只存哈希与受控引用；每条关键事件先落盘再执行不可逆动作。会话状态另存小型快照，日志损坏时仍可定位最后提交点。为排障提供按根任务聚合的视图，把模型调用、工具调用、策略决策和外部副作用串成因果链，并设置保留期限与访问权限。

## 反例

只用临时终端输出，重启即断史；把所有模型响应全文塞入一个巨大 JSON，导致写入中断后整份日志不可解析；或在动作完成后才记日志，使崩溃窗口内的真实副作用永远无法审计。
